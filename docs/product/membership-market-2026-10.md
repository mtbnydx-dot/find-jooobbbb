## 2. 首批服务对象与价值主张

先服务国内校招、毕业两三年内转岗，以及有跨专业求职需要的用户。对专业不同的用户共享同一套流程，但推荐依据、技能缺口、备考路径分别计算：

1. 找到可申请机会：多源去重、源链接、最后更新时间、截止日期、资格条件和字段未知提示。
2. 决定优先级：个人画像、城市/行业/工作方式偏好、薪资原文、匹配解释和不满足条件。
3. 持续推进：收藏与投递阶段、下一步、提醒、保存搜索、跨设备同步。
4. 针对性准备：岗位关联路径、原创练习、错题复习、答案解析、准备清单。
5. 得到售后：岗位纠错、账户问题、订单和会员权益查询，能看见处理状态与回复。

不把“保证录用”“内部保过”“购买岗位原链接”“未上线的真人辅导”列为会员权益。平台提供信息整理与准备工具，雇主决定招聘结果。

## 4. 最小商业闭环

### 用户侧

- 套餐页展示总价、天数、非自动续费、具体额度、当前套餐、到期时间和剩余额度。
- 支付渠道未接通时使用“申请开通/联系核验”，明确未自动扣款、申请不代表已付款；用户可查看申请状态与处理原因。
- 订单保存提交时套餐名称、价格、期限和权益快照。后续管理员改价不追溯修改旧订单金额。
- 已生效订单显示实际起止时间；续费同档位从较晚的当前时间或有效期末延长。拒绝、取消、退款应有独立状态和理由。
- 支持用户发起售后、会员问题和岗位纠错，能在同一页面查看管理员回复；不会把私人问题公开给其他用户。

### 管理侧

- 总览显示用户、有效会员、待处理申请、待回复工单和岗位质量状态，指标来自数据库。
- 套餐价格/期限/权益可配置；下架停止新购，不直接删除历史订单。
- 会员审批需记录操作人、时间、开通依据和备注；确认外部收款时记录外部交易参考号，不能把“人工开通”直接记为支付平台回调成功。
- 重复审批/重复提交不可重复延长会员。每次授权、撤销、角色/账户状态变更都留下审计记录。
- 管理员可禁用/恢复账号；禁用应终止会话。防止删除或禁用最后一个可用管理员。
- 用户查询、授权、订单和工单要支持搜索、状态筛选与分页；内容编辑角色不能获得订单、角色分配和敏感配置权限。

真实在线支付的必要接入点是商户渠道、服务器验签回调、订单对账和退款结果。未配置前不生成假的扫码支付成功，不把人工核验当作自动收款。退款申请与执行结果分开，用户不能靠自己提交状态获得权益。

## 5. 本轮优先级与验收

| 优先级 | 缺口 | 交付验收 |
| --- | --- | --- |
| P0 | 固定套餐缺少履约记录 | 用户申请 → 管理员审核 → 权益生效 → 用户可见到期，重复操作不重复授予 |
| P0 | 后台只有角色/套餐按钮 | 总览、用户状态、套餐管理、申请队列、工单、审计入口可实际操作 |
| P0 | 用户错误无反馈闭环 | 岗位纠错/会员问题 → 后台回复 → 用户看到回复及状态 |
| P0 | 画像/收藏被共享修改的历史问题 | 至少两个账号交叉测试：画像、状态、订单、工单、练习数据都只属于本人 |
| P1 | 求职信息重复检索、容易错过截止 | 保存搜索与提醒落地，过期岗位明确标识，来源和更新时间可见 |
| P1 | 会员内容不足 | 真实内容数量、原创标记、题目版本和发布审核；未实现的服务不售卖 |
| P1 | 移动端后台难操作 | PC 与窄屏下完成申请、审核、筛选、答题和查看错误提示，无横向溢出 |
| P2 | 自动支付/消息送达 | 有实际渠道时完成沙箱与真实最小金额闭环；邮件/推送需要送达及退订验证 |

关键自动化应覆盖越权读取、重复审批、到期回退、套餐改价不改历史单、禁用后会话失效、最后管理员保护及会员额度。浏览器验收应跑用户提交和管理员处理的成对流程，而不是只检查首页加载。

## 6. 上线后验证价格与权益

先记录四周的实际使用数据，再决定价格是否调整。建议指标：注册到画像完成率、有效岗位收藏率、投递阶段更新率、保存搜索使用率、备考完成率、会员页访问到申请率、申请到开通率、到期复购率、退款/争议和每活跃付费用户服务成本。分别按应届/转行、岗位族、30/90 天期限观察，不将“申请数量”当“已支付收入”。

起步可对已明确同意的内测用户人工授予 7 天体验，记录授权来源与到期时间；不自动扣款。采访未升级用户，区分“价格高”“没有需要”“岗位质量差”“内容不足”和“支付困难”，优先解决实际价值缺口。
