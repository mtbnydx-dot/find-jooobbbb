# 商业化发布路线图

> 本路线图区分“代码中已经存在的能力”“当前分支正在建设的能力”和“依赖外部资质或运营资源的能力”。只有通过对应验收门槛后，能力才能对外宣称已接通。

## 1. 当前分支状态（2026-08-31）

当前产品化分支已经真实具备：

- 飞书、腾讯文档、HTML、JSON 和 Excel 等多来源采集。
- 云端调度、运行记录、来源登录会话和跨来源去重。
- 全局岗位目录与独立的多用户画像、岗位状态、下一步、提醒和私人备注。
- DeepSeek 全局画像批量评估、缓存和推荐解释。
- DDL 摘要、面经链接搜索、Excel 导出和响应式管理看板。
- `product.db` 中的用户、散列密码、会话、`user/content_editor/admin` 角色和服务端权限校验。
- 每用户多专业/多岗位/多地点/多技能画像，以及确定性的用户级匹配解释与缺口提示。
- Free/Pro/Coach 套餐目录、服务端权益与每日用量限制、管理员人工授权和到期回退。
- 8 条备考路径、24 道原创种子题、逐题评分/解析和用户进度隔离。
- 响应式 PC/手机 PWA、Android/Apple 安装图标、安全区适配、深链回退和构建产物离线壳。
- `/app/` 用户产品入口、`/app/admin/users` 用户授权入口和仅管理员可进入的 `/ops` 运营入口。

当前分支仍未真实具备：

- 用户级 AI 推荐缓存（目前用户端为确定性画像匹配；旧 DeepSeek 结果不会冒充个人结果）。
- 多份独立职业画像、错题本、学习计划和题目版本历史（当前是一个包含多专业的画像与练习进度）。
- 真实订单、退款、续费和支付 webhook；当前支付 provider 未配置时明确拒绝结账。
- 可验证送达的产品邮件、Web Push 或原生推送。
- Android/iOS 商店签名包、原生推送和应用上架；当前交付是浏览器与 PWA。
- 可商业使用的企业真题版权库和可靠薪资数据库。
- 管理操作的完整审计账本、邮箱验证、找回密码、账号删除与商业化合规流程。

## 2. 路线图原则

1. 先隔离用户数据，再扩大用户数量。
2. 先建立服务端权益，再接支付渠道。
3. 先提供有来源的岗位事实，再做 AI 解释。
4. 先用原创小题库验证学习闭环，再购买或引入大规模内容。
5. 先完成响应式 Web 和 PWA，再决定是否需要原生商店交付。
6. 任何依赖商户、邮件域名、推送证书、内容授权或人工服务的能力，都必须设置显式发布门槛。

## 3. 里程碑 M1：产品底座的完成项与发布前门槛

目标：形成可在本机演示、可测试、但不伪装真实商业交易的多用户求职闭环。

### 3.1 产品与数据底座（已完成）

- 拆分全局岗位内容和用户私有岗位状态。
- 增加用户、会话、角色、职业画像、用户岗位状态、推荐、套餐、权益、用量和备考实体。
- 保留现有采集与 canonical 岗位 ID，避免破坏去重结果。
- 已提供默认 dry-run、指定归属账号、幂等、数量核对和 SQLite 备份的旧状态/备注/自选岗位迁移工具；迁移后的自选岗位只对归属用户可见。

### 3.2 用户闭环（已完成第一版）

- 注册、登录、退出和当前用户。
- 完成教育经历、专业、目标岗位、地区和薪资偏好引导。
- 查看岗位目录、个性推荐理由和资格风险。
- 收藏、投递、更新阶段、下一步和私人备注。
- 根据画像推荐备考路径并保存练习进度；按投递阶段自动生成学习计划仍属后续能力。
- 查看 Free、Pro、Coach 权益和当前用量。

### 3.3 管理员闭环（部分完成）

- 普通用户界面不再显示信息源、服务器登录、全局 AI Key 和采集运行详情。
- 已完成管理员用户角色、人工套餐授权和独立运营入口。
- 待完成：分类维护 UI、题库草稿/发布/下架、关键授权和内容发布审计账本。

### 3.4 内容种子（演示种子已完成，商业内容工作流待完成）

- 已建立专业、学历、岗位族、行业、地区和技能的第一版规则分类。
- 已把 8 条备考路径和 24 道原创种子题接入持久化、用户答题、评分与解析。
- 待完成：技能标签、版权状态、草稿/发布/下架、版本历史，以及销售、客户成功、人力、法务、医疗、教育、设计和作品集等内容覆盖。

### 3.5 跨端交付（响应式 Web/PWA 已完成，真机与商店交付待完成）

- 已交付响应式 Web，共用同一业务接口，并具备 PWA manifest、图标、service worker、深链回退与离线壳。
- 待完成：应用内安装/更新提示，以及 Android Chrome、iOS Safari 真机核心流程验收；当前自动化 1440、834、390、360 像素验收只作为补充。

### 3.6 M1 发布门槛

- 两个测试账号不能读取或修改对方的画像、状态、备注、推荐和答题记录。
- 不同专业画像对同一岗位目录产生不同推荐和解释。
- 薪资未知、面议和跨币种能够正确展示，不出现按 0 排序。
- 套餐限制由服务端执行，人工授权后立即生效且可审计。
- 未配置支付时，升级接口明确返回“支付服务未配置”，前端无支付成功动画或订单号。
- 当前静态 ¥0/¥39/¥129 月价只作为产品假设展示，不产生真实订单或付费权益。
- 普通用户无法调用管理员和采集接口。
- 旧数据迁移前后岗位、备注、状态和自选记录数量可核对。
- 桌面、iOS Safari 和 Android Chrome 至少完成登录、画像、找岗位、改进度、答题和套餐查看。

## 4. 里程碑 M2：真实邮件与通知

### 4.1 邮件

依赖项：

- 已验证发件域名和 SMTP 或邮件服务商账号。
- SPF、DKIM、DMARC 配置。
- 模板、退订、退信和投诉处理。
- 用户通知偏好、频率限制和发送审计。

验收：

- 注册验证、重置密码、DDL 提醒和周报能发送到真实测试邮箱。
- 退订后不再发送营销邮件，必要事务邮件单独分类。
- 退信和供应商错误可观测，不把“任务入队”当作“邮件送达”。

### 4.2 Web Push

依赖项：VAPID 密钥、service worker、用户授权和订阅保存。

验收：Android Chrome、桌面 Chrome/Edge 完成真实设备送达；iOS 仅在符合系统和安装条件的设备上测试后才宣传支持。

### 4.3 原生推送

依赖项：Apple APNs、Firebase Cloud Messaging、应用签名、设备令牌和通知偏好。

在原生应用尚未构建时，不能把站内通知或 Web Push 称为“iOS/Android 原生推送”。

## 5. 里程碑 M3：真实支付与订阅

### 5.1 渠道选择

可按目标市场分阶段选择：

- 国际银行卡：Stripe 等服务商。
- 中国大陆：微信支付、支付宝等具有相应商户资质的渠道。
- iOS/Android 数字权益：上架前评估对应商店的应用内购买和外部支付规则。

渠道规则会变化，接入时必须查验服务商和商店的最新官方文档。

### 5.2 接入前置

- 企业或个体商户账号、结算账户和必要资质。
- 商品、价格、币种、税费、发票、退款和用户协议。
- 测试与生产密钥分离，密钥只保存在服务端环境中。
- 订单、订阅、支付事件、退款和权益记录。

### 5.3 正确状态流

```text
客户端发起结账
  -> 服务端创建支付会话
  -> 用户在支付渠道完成操作
  -> 支付渠道签名 webhook
  -> 服务端幂等记录事件
  -> 授予或续期 entitlement
  -> 客户端重新读取当前权益
```

客户端回跳页面不能作为付费成功依据。权益必须由已验证 webhook 或管理员人工授权产生。

### 5.4 验收

- 测试环境覆盖成功、失败、取消、重复 webhook、退款、续费失败和取消续费。
- 相同 webhook 重放不会重复授权。
- 退款或订阅到期后权益按规则回收，历史订单仍可审计。
- 价格页、结账页、账单和实际扣款币种一致。
- Coach 服务额度与预约交付记录绑定，不能只通过套餐布尔值表示。

## 6. 里程碑 M4：内容版权与题库规模化

### 6.1 内容来源分类

- `original`：平台原创并保存作者和版本。
- `licensed`：有书面授权、范围、期限和地区。
- `public_reference`：仅引用允许使用的公开资料，并保存链接和许可信息。
- `user_contributed`：有投稿协议、审核和侵权处理。

### 6.2 发布工作流

```text
草稿 -> 内容复核 -> 答案校验 -> 版权确认 -> 发布 -> 修订或下架
```

每次发布必须保留题干、答案、解析、作者、复核人、版权状态和版本。用户历史答题应关联题目版本，避免修改答案后旧得分无法解释。

### 6.3 不能直接使用的内容

- 来源不明的“企业真题合集”。
- 需要付费或登录后才能查看但未获得授权的题目。
- 从社区、培训机构或招聘平台大规模复制的题干和解析。
- AI 模仿真实企业试题生成后被宣传成“官方真题”的内容。

### 6.4 验收

- 所有收费内容都有可查询的权利状态。
- 发现错误或侵权时可按版本下架，不破坏用户练习记录。
- 主观题明确区分规则评分、AI 反馈和真人反馈。

## 7. 里程碑 M5：薪资数据产品

### 7.1 数据来源

- 岗位原始 JD 中披露的薪资。
- 获得授权的招聘或薪资数据提供商。
- 用户自愿匿名提交的 Offer，需有同意、脱敏和最小样本规则。
- 管理员核实与纠错记录。

### 7.2 规范化

- 保留原文、币种、周期、发薪月数、奖金、股权和福利。
- 记录解析方法、来源、新鲜度和置信度。
- 跨币种换算记录汇率来源和日期。
- 样本不足时不展示精确市场分位数。

### 7.3 验收

- 所有展示的薪资都有来源和更新时间。
- `未知`、`面议`、实习日薪/月薪和正式年薪不会被错误混排。
- 市场区间有最小样本门槛，并向用户显示样本量。
- AI 估算值只能进入单独的估算字段，不能覆盖已验证事实。

## 8. 里程碑 M6：Android/iOS 原生上架

### 8.1 决策门槛

只有当 PWA 的留存、通知或系统能力确实受限，且用户量足以承担双平台维护成本时，再进入商店交付。

### 8.2 必要工作

- 选择 Capacitor 包装或原生客户端方案。
- Android application ID、签名密钥、构建流水线和 Play Console。
- iOS bundle ID、证书、provisioning profile、App Store Connect。
- 隐私清单、权限说明、账号删除、用户协议和商店素材。
- 深链、文件上传、分享、推送、登录、支付和网络失败处理。
- 不同尺寸、系统版本、深色模式和无障碍真机验证。

### 8.3 验收

- 生产签名包安装到真实设备并通过核心流程。
- 商店审核通过且公开页面可访问后，才可宣称“已上架”。
- 若销售数字权益，支付流程符合对应商店当前政策。
- Web、Android 和 iOS 使用相同服务端权限与权益逻辑。

## 9. Coach 服务里程碑

Coach 套餐不是纯代码功能。上线前必须有：

- 真实教练、擅长方向、可预约时间和身份核验。
- 简历批改与模拟面试的交付物标准。
- 预约、改期、缺席、退款和争议处理。
- 服务额度、消耗记录、用户授权和资料访问回收。
- 服务质量评价、申诉和管理员复核。

没有上述运营闭环时，可以展示“辅导服务内测申请”，不能直接售卖并承诺固定交付。

## 10. 不能伪装为已接通的能力

| 页面或代码现象 | 不能宣称 | 达成条件 |
|---|---|---|
| 展示套餐卡片 | 已支持会员购买 | 真实支付、webhook、订单、退款和权益已验证 |
| 管理员人工改套餐 | 已接订阅系统 | 续期、取消、失败扣款和事件幂等已完成 |
| SMTP 配置项存在 | 邮件稳定送达 | 域名验证、真实收件测试、退订和退信处理通过 |
| 浏览器站内提示 | 支持手机推送 | Web Push 或 APNs/FCM 在真实设备送达 |
| 响应式手机页面 | 已有 Android/iOS App | 生产签名应用完成真机测试和商店上架 |
| manifest 文件存在 | PWA 已完成 | service worker、图标、安装和离线边界通过验证 |
| AI 生成练习题 | 企业官方真题 | 获得内容授权并通过编辑审核 |
| AI 猜测薪资 | 真实薪资数据 | 有来源、更新时间、样本和规范化规则 |
| AI 主观题反馈 | 真人导师批改 | 真实教练完成交付并留下记录 |
| 任务进入发送队列 | 通知已送达 | 服务商接受且设备或邮箱测试可验证 |
| 自动化移动尺寸截图 | 已兼容所有手机 | Android/iOS 真机核心流程通过 |

## 11. 发布与回滚要求

每个里程碑发布前：

- 备份岗位目录、数据库、浏览器会话和环境配置。
- 记录数据库迁移版本，并提供向前修复或回滚说明。
- 使用测试账号覆盖 Free、Pro、Coach 和管理员权限。
- 核对旧用户状态、备注、自选岗位、AI 结果和来源数量。
- 在独立环境完成测试，未经单独批准不直接替换 `zlkjob.com` 生产版本。

生产灰度时：

- 先向内部账号或小比例用户开放。
- 观察登录失败、推荐成本、接口错误、通知退信、支付事件和数据隔离。
- 保留旧看板只读回退入口，直到新用户状态迁移得到确认。

## 12. 建议成功指标

第一阶段重点验证用户价值，不以注册量代替效果：

- 完成职业画像并保存至少 3 个岗位的激活率。
- 推荐曝光到查看、收藏和投递的转化。
- 投递到笔试、面试和 Offer 的阶段变化。
- 备考诊断完成率、学习计划完成率和错题复习率。
- Free 达到权益边界后的升级意愿。
- Pro 试用到付费、续费、退款和流失。
- AI 单次有效推荐成本和题库内容维护成本。

这些指标用于发现产品问题，不能把相关性直接解释成平台导致用户获得 Offer。
