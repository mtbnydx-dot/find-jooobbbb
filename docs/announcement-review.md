# 原公告核验与事实补全

入口：产品管理后台 → 原公告核验（管理员或内容编辑）。用户岗位详情有可展开的逐字段证据。

## 操作流程

1. 搜索或粘贴岗位 ID，每批最多 50 条，明确发起核验。同批次同公告仅请求一次；各岗位分别判断。
2. 查看公司、具体岗位、届次和原文适用范围。勾选字段、填写理由后采纳；不可靠结果拒绝。
3. 自动读取受限、动态页面或附件，可人工打开原文并摘录短证据，形成待审核候选。不能把搜索摘要当原文。
4. 采纳后立即用于当前目录、筛选和后续个人 AI 评估。原始采集数据不改，用户自选、进度、画像不删除；已有人工更正优先。

## 事实边界

- 按规定执行、面议、未知，不生成数字薪资。生活补助和科研经费不是工资。
- 金额、币种、周期、发薪月数作为一组；更新薪资原文时清除没有一并确认的旧单位。
- 报名截止已过和明确停止招聘可以作为关闭依据；网页 404、登录、验证码、超时不能证明停招。
- 长期招聘、招满即止、网站可访问不证明还有空缺。核验时间不是实时招聘方确认。
- 多岗位表格/正文仅提取唯一对应行或段落。总公告的通用条件必须经人工明确确认；不把一岗要求套给全部岗位。
- 复用 URL 不等于同一届次；不同明确届次的来源暂停自动补全并提示冲突。

## 多来源与已有数据

该流程只更新既有 canonical 岗位，不创建新岗位；沿用别名关系，保留原记录 ID 与审计。别名迁移时薪资证据仍整组处理；人工覆盖冲突保留 canonical 人工记录，旧值留审计。

历史采集器的同公司/岗位/地点归并可能已把不同届次合在一起，本次不自动拆分这种旧记录，也不移动用户自选。明确冲突只阻止继续自动补全。未来若改采集器的身份规则，应另做稳定 ID 与历史用户状态迁移验证，不能仅凭同 URL 合并。

## 运行与限制

核验队列只消费管理员发起的任务，没有定时创建抓取任务，不调用付费模型。访问公共网页遵守站点抓取限制，不使用用户登录 Cookie、不绕过验证码；跨站跳转须重新核对。单任务失败可重试三次，取消不撤销已采纳事实。正文缓存仅在任务处理中短期使用，完成后仅留短证据和摘要。

首批人工复核内容见 `server/product/reviewed-announcements-20261023.json`。脚本 `server/scripts/apply_reviewed_announcements.js` 默认只预览；显式 `--apply --data-dir ... --actor-id ... --catalog ...` 才在事务中逐项形成审核/采纳记录，重复执行不重复导入，并校验个人数据未变。不会自动随发布或启动导入。

此版本不自动解析图片、PDF、Word 附件或登录后的动态页面。精确数值薪资缺少官方依据时继续留空，不使用模型估算冒充招聘待遇。定时备份不因本功能开启。
